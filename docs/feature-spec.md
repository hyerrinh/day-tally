# 1. 공통 기능 정책

## COMMON-001 사용자 데이터 분리

### 기능 설명

모든 사용자 데이터는 로그인한 계정을 기준으로 분리한다.

### 관련 데이터

- 사용자
- 카테고리
- 행동
- 행동 기록
- 사용자 설정

### 처리 규칙

- 모든 사용자 소유 데이터는 `userId`를 기준으로 조회·생성·수정한다.
- 다른 사용자의 데이터에는 접근할 수 없다.
- 로그아웃하면 현재 사용자 데이터와 관련된 로컬 캐시를 제거한다.

---

## COMMON-002 날짜 및 시간 기준

### 기능 설명

행동을 수행한 날짜와 시스템상 생성·수정 시각을 분리하여 관리한다.

### 데이터 항목

| 항목 | 형식 | 설명 |
| --- | --- | --- |
| `recordDate` | Date | 사용자가 행동을 수행한 날짜 |
| `createdAt` | DateTime | 기록이 최초 생성된 시각 |
| `updatedAt` | DateTime | 기록이 마지막으로 수정된 시각 |

### 처리 규칙

- `recordDate`는 `YYYY-MM-DD` 형태의 날짜값으로 관리한다.
- `recordDate`에는 시각과 시간대 정보를 포함하지 않는다.
- `createdAt`, `updatedAt`은 UTC 기준으로 저장한다.
- 화면 표시가 필요한 경우 사용자 현지 시간으로 변환한다.
- 기존 기록의 `recordDate`는 사용자의 시간대가 변경되어도 자동 변경하지 않는다.
- 오늘 및 미래 날짜 판단에는 사용자 기기의 현지 날짜를 사용한다.
- MVP에서는 기기 날짜를 신뢰한다.
- 서버 검증이 간단하게 가능하다면 서버 시각과 사용자 시간대를 함께 사용하여 검증할 수 있다.

---

## COMMON-003 요청 중 중복 실행 방지

### 처리 규칙

- 생성·수정·삭제·로그인·탈퇴 요청 처리 중에는 같은 실행 버튼을 비활성화한다.
- 동일 요청을 짧은 시간 안에 반복 전송하지 않는다.
- 요청이 완료되면 버튼을 다시 활성화한다.
- 요청 실패 시 사용자가 재시도할 수 있다.

---

## COMMON-004 실패 시 입력값 유지

### 처리 규칙

저장 또는 수정에 실패한 경우 다음 원칙을 적용한다.

- 현재 화면이나 바텀시트를 닫지 않는다.
- 사용자가 입력한 값을 유지한다.
- 실패 원인을 알리는 메시지를 표시한다.
- 사용자는 기존 실행 버튼으로 다시 시도할 수 있다.

---

## COMMON-005 이름 입력 공통 규칙

### 적용 대상

- 카테고리 이름
- 행동 이름

### Validation

- 필수값이다.
- 최대 15자까지 입력할 수 있다.
- 앞뒤 공백은 제거한다.
- 공백만 입력할 수 없다.
- 특수문자와 이모지를 허용한다.
- 제어문자 등 화면 표시가 불가능한 문자는 허용하지 않는다.
- 앞뒤 공백과 영문 대소문자만 다른 이름은 동일한 이름으로 판단한다.
- 내부 공백 차이는 서로 다른 이름으로 판단한다.

### 예시

```
운동
 운동
운동
```

위 이름은 동일하게 판단한다.

```
자기계발
자기 계발
```

위 이름은 서로 다른 이름으로 판단한다.

---

## COMMON-006 소요 시간 공통 규칙 (V1.1 추가)

### 적용 대상

- 행동 기록의 `durationMinutes`
- 행동의 기본 시간 `defaultDurationMinutes`

### Validation

- `null`(시간 없음) 또는 1~1,439분
- 1분 단위 정수
- `0`은 저장하지 않으며 `null`로 변환한다.

# 2. 인증 및 계정

## AUTH-001 SNS 로그인

### 기능 설명

Google 또는 Apple 계정을 사용하여 앱에 로그인한다.

### 관련 화면

- 로그인 화면
- 홈 화면

### 진입 조건

- 비로그인 상태

### 지원 방식

- Google 로그인
- Apple 로그인

### 구현 순서 (V1.1 추가)

- Google 로그인을 먼저 구현한다.
- Apple 로그인은 iOS 출시 전에 추가한다.

### 처리 규칙

- 이메일과 비밀번호를 직접 입력하는 로그인은 제공하지 않는다.
- (V1.1 변경) Google 계정과 Apple 계정의 이메일이 같으면 같은 앱 계정으로 처리한다. (Supabase 자동 연결)
- Apple 이메일 가리기로 생성된 중계 이메일은 다른 이메일이므로 별도 앱 계정이 된다.
- 다른 이메일 계정을 직접 연결하는 기능은 제공하지 않는다.
- 로그인 성공 후 세션을 유지한다.
- 사용자가 직접 로그아웃하거나 세션이 만료되기 전까지 로그인 상태를 유지한다.

### 성공 결과

#### 기존 사용자

- 사용자 데이터를 조회한다.
- 홈 화면으로 이동한다.
- 선택 날짜를 오늘로 설정한다.
- 마지막으로 선택한 활성 카테고리가 있으면 복원한다.

#### 신규 사용자

- 앱 사용자 계정을 생성한다.
- 기본 카테고리와 행동을 생성한다.
- 기본 데이터 생성 완료 후 홈으로 이동한다.

### 실패 처리

- 로그인 화면을 유지한다.
- 로그인 실패 안내를 표시한다.
- 일부 인증 정보가 저장되었다면 제거한다.

---

## AUTH-002 신규 사용자 기본 데이터 생성

### 기능 설명

처음 가입한 사용자에게 기본 카테고리와 기본 행동을 생성한다.

### 기본 데이터

| 카테고리 | 행동 |
| --- | --- |
| 일상 | 밥 먹기, 청소, 설거지 |
| 운동 | 스트레칭, 러닝 |
| 커리어 | 회사 |

### 처리 규칙

- 사용자 계정과 기본 데이터의 초기화가 완료되어야 가입 완료로 처리한다.
- 일부 카테고리나 행동만 생성된 상태로 홈에 진입시키지 않는다.
- 초기화 실패 시 재시도할 수 있어야 한다.
- 재시도 시 같은 기본 데이터가 중복 생성되지 않아야 한다.

### 성공 결과

- 기본 데이터가 모두 생성된다.
- 첫 번째 활성 카테고리 또는 기본 선택 카테고리를 홈에 표시한다.

### 실패 처리

- 홈 진입을 차단한다.
- 초기화 실패 안내와 재시도 수단을 제공한다.

---

## AUTH-003 로그아웃

### 기능 설명

현재 로그인 세션을 종료한다.

### 관련 화면

- 설정
- 계정 관리
- 로그아웃 확인 팝업

### 처리 규칙

- 로그아웃 전 확인 팝업을 표시한다.
- 서버에 저장된 사용자 데이터는 삭제하지 않는다.
- 현재 기기에 저장된 사용자 관련 정보를 제거한다.

### 로컬 삭제 대상

- 인증 토큰 및 세션 정보
- 사용자 정보
- 캐시된 카테고리·행동·기록
- 마지막 선택 카테고리
- 작성 중이던 기록 입력값
- 사용자별 임시 상태

### 성공 결과

- 로그인 화면으로 이동한다.
- 이전 사용자의 정보가 화면에 남지 않는다.
- 같은 계정으로 다시 로그인하면 서버 데이터를 다시 조회한다.

### 실패 처리

- 로그아웃이 완료되지 않은 경우 기존 화면을 유지한다.
- 오류 안내를 표시한다.

---

## AUTH-004 회원 탈퇴

### 기능 설명

앱 사용자 계정과 해당 계정에 속한 서비스 데이터를 영구 삭제한다.

### 관련 화면

- 계정 관리
- 회원 탈퇴 안내
- 최종 확인 팝업

### 확인 절차

1. 모든 기록과 설정이 삭제된다는 안내를 표시한다.
2. 복구할 수 없다는 내용을 표시한다.
3. 최종 탈퇴 버튼을 한 번 더 선택해야 탈퇴 요청을 실행한다.

### 삭제 대상

- 앱 사용자 계정
- 카테고리
- 행동
- 행동 기록
- 사용자 설정
- 사용자 관련 서비스 데이터

### 처리 규칙

- MVP에서는 SNS 재인증을 필수로 요구하지 않는다.
- 서비스 데이터는 탈퇴 완료 시 실제 삭제한다.
- 모든 필수 데이터 삭제가 완료되어야 탈퇴 성공으로 처리한다.
- 계정만 삭제되고 행동 기록이 남는 부분 성공 상태를 허용하지 않는다.
- 법적·보안상 보관이 필요한 최소 로그는 개인정보처리방침에 따라 별도 보관할 수 있다.
- 탈퇴 후 같은 SNS 계정으로 다시 로그인하면 신규 사용자로 처리한다.
- 탈퇴된 데이터는 복원하지 않는다.

### 성공 결과

- 로컬 사용자 데이터를 제거한다.
- 로그인 화면으로 이동한다.

### 실패 처리

- 현재 화면을 유지한다.
- 계정과 데이터를 탈퇴 전 상태로 유지한다.
- 탈퇴 실패 안내를 표시한다.

# 3. 홈 및 날짜 선택

## HOME-001 홈 초기화

### 기능 설명

로그인 후 사용자가 행동을 선택하고 기록을 확인할 수 있는 홈 데이터를 초기화한다.

### 관련 화면

- 홈

### 초기 상태

| 항목 | 초기값 |
| --- | --- |
| 선택 날짜 | 오늘 |
| 선택 카테고리 | 마지막 선택 카테고리 |
| 마지막 선택 카테고리 사용 불가 시 | 첫 번째 활성 카테고리 |

### 처리 규칙

- 앱을 새로 실행하면 선택 날짜는 항상 오늘로 설정한다.
- 마지막으로 선택한 활성 카테고리는 앱 재실행 후에도 복원한다.
- 마지막 선택 카테고리가 숨김 상태이면 첫 번째 활성 카테고리를 선택한다.
- 설정 등 다른 화면에 진입했다가 홈으로 돌아오면 기존 선택 날짜를 유지한다.
- 앱이 백그라운드에 있는 동안 자정이 지나도 선택 날짜를 자동 변경하지 않는다.
- 백그라운드 복귀 시 오늘 표시는 현재 날짜로 갱신한다.

---

## HOME-002 카테고리 선택

### 기능 설명

홈에서 활성 카테고리를 선택하고 해당 카테고리의 활성 행동을 표시한다.

### 처리 규칙

- 활성 카테고리만 홈에 표시한다.
- 카테고리를 선택하면 해당 카테고리의 활성 행동 목록을 표시한다.
- 날짜 또는 주를 변경해도 선택 카테고리를 유지한다.
- 선택 카테고리를 로컬 사용자 설정에 저장한다.
- 행동이 없는 활성 카테고리도 표시한다.
- 카테고리 정렬은 생성 순서를 따른다.

### 빈 상태

선택 카테고리에 활성 행동이 없는 경우 행동 추가 안내를 표시한다.

---

## HOME-003 날짜 선택

### 기능 설명

주간 날짜 영역 또는 월간 캘린더에서 조회할 날짜를 선택한다.

### 처리 규칙

- 과거, 오늘, 미래 날짜를 모두 선택할 수 있다.
- 선택 날짜가 변경되면 다음 데이터를 갱신한다.
    - 상단 연·월
    - 선택 날짜 상태
    - 날짜별 기록 요약
    - 기록 빈 상태
    - 신규 기록 가능 여부
- 선택 카테고리는 유지한다.
- 이미 선택된 오늘 날짜를 다시 눌러도 별도 동작을 수행하지 않는다.

### 날짜별 권한

| 날짜 | 조회 | 생성 | 수정 | 삭제 |
| --- | --- | --- | --- | --- |
| 과거 | O | O | O | O |
| 오늘 | O | O | O | O |
| 미래 | O | X | X | X |

---

## HOME-004 주간 이동

### 기능 설명

주간 날짜 영역을 좌우로 스와이프하여 이전 주 또는 다음 주로 이동한다.

### 처리 규칙

- 주간 날짜 영역 안에서 시작된 가로 제스처에만 반응한다.
- 오른쪽 스와이프 시 이전 주로 이동한다.
- 왼쪽 스와이프 시 다음 주로 이동한다.
- 과거 및 미래 주 이동 범위를 별도로 제한하지 않는다.
- 이동한 주에 선택 날짜가 포함되지 않는 경우 주 이동 정책에 따라 적절한 날짜를 선택한다.
- 상단 연·월은 항상 현재 선택 날짜를 기준으로 표시한다.

---

## HOME-005 미래 날짜 행동 비활성화

### 기능 설명

미래 날짜에서는 행동 목록을 조회할 수 있지만 새로운 기록을 생성할 수 없다.

### 처리 규칙

- 행동 버튼을 비활성 상태로 표시한다.
- 탭해도 즉시 기록하지 않고, 길게 눌러도 기록 입력 시트를 열지 않는다. (V1.1 변경)
- 비활성 행동을 눌렀을 때 미래 날짜에는 기록할 수 없다는 안내를 표시할 수 있다.
- 단순 비활성 처리로도 충분한 경우 별도 동작을 생략할 수 있다.

---

## HOME-006 날짜별 기록 요약

### 기능 설명

선택 날짜의 행동 기록을 카테고리와 행동 단위로 묶어 표시한다.

### 요약 기준

- 동일한 `recordDate`
- 동일한 `actionId`

### 계산 항목

| 항목 | 계산 방식 |
| --- | --- |
| 기록 횟수 | 해당 행동 기록 전체 개수 |
| 시간 합계 | `durationMinutes`가 존재하는 기록의 합계 |

### 표시 규칙

- 동일 행동의 기록은 한 행으로 묶는다.
- 기록이 한 건이면 `1회`를 표시한다.
- 시간 합계가 있으면 `2회 · 50분` 형태로 표시한다.
- 시간이 입력된 기록이 하나도 없으면 횟수만 표시한다.
- 60분 미만은 `30분` 형태로 표시한다.
- 60분 이상은 `1시간 30분` 형태로 표시한다.
- 일부 기록에만 시간이 있어도 입력된 시간의 합계를 표시한다.
- 숨긴 행동이나 숨긴 카테고리의 과거 기록도 표시한다.
- 기록 요약은 별도 영구 데이터로 저장하지 않고 기록 데이터를 기준으로 계산할 수 있다.

### 정렬

- 카테고리는 생성 순서 기준으로 표시한다.
- 행동은 생성 순서 기준으로 표시한다.

# 4. 행동 기록

## REC-001 행동 기록 생성 (V1.1 변경)

### 기능 설명

선택한 행동에 대해 새로운 기록 한 건을 생성한다.

동일한 행동은 같은 날짜에 여러 번 기록할 수 있으며, 기존 기록을 덮어쓰지 않는다.

기록 방법은 두 가지다.

| 방법 | 동작 |
| --- | --- |
| 탭 (즉시 기록) | 행동 버튼을 탭하면 바로 기록 한 건을 생성한다. |
| 길게 누르기 (기록 입력 시트) | 시간(±)과 메모를 입력하는 시트를 열고, 저장 버튼으로 기록을 생성한다. |

### 관련 화면

- 홈
- 기록 완료 토스트
- 기록 입력 바텀시트
- 기록 상세·편집 바텀시트

### 진입 조건

- 로그인 상태
- 선택 날짜가 오늘 또는 과거
- 선택 행동이 활성 상태
- 선택 행동의 소속 카테고리가 활성 상태

### 입력 항목

| 항목 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `actionId` | UUID | O | 기록 대상 행동 |
| `recordDate` | Date | O | 행동을 수행한 날짜 |
| `durationMinutes` | Number/null | X | 소요 시간 |
| `memo` | String/null | X | 메모 |

### Validation

| 항목 | 규칙 |
| --- | --- |
| 날짜 | 저장 시점 기준 미래 날짜 불가 |
| 행동 | 존재하며 현재 사용자 소유여야 함 |
| 행동 상태 | 숨김 상태 저장 불가 |
| 카테고리 상태 | 숨김 상태 저장 불가 |
| 소요 시간 | `null` 또는 1~1,439분 (COMMON-006) |
| 시간 단위 | 1분 단위 |
| 메모 | 최대 500자 |
| 메모 공백 | 앞뒤 공백 제거 |
| 빈 메모 | `null` 처리 |

### 탭 즉시 기록 처리 규칙

- 행동에 기본 시간이 있으면 `durationMinutes`로 저장하고, 없으면 `null`로 저장한다.
- 메모는 `null`로 저장한다.
- 저장 요청 처리 중에는 같은 행동의 중복 요청을 차단한다.
- 저장 성공 시 기록 완료 토스트를 표시한다.
- 토스트에는 `되돌리기`와 `수정`을 제공한다.
    - `되돌리기`: 방금 생성한 기록을 삭제한다. 확인 팝업 없이 실행한다.
    - `수정`: 방금 생성한 기록의 상세·편집 바텀시트를 연다. (REC-004)
- 토스트가 사라진 뒤에는 기록 상세 화면에서 수정·삭제한다.

### 기록 입력 시트 처리 규칙

- 행동에 기본 시간이 있으면 시간 초기값으로 적용하고, 없으면 `시간 없음`으로 시작한다.
- ± 버튼은 행동별 ± 단위만큼 시간을 바꾼다. (ACT-004)
- 사용자는 기본 시간을 수정하거나 제거할 수 있다.
- 시간과 메모가 모두 없어도 저장할 수 있다.
- 바텀시트가 열린 후 행동이 숨겨진 경우 저장 시점에 다시 검증한다.

### 공통 처리 규칙

- 저장할 때마다 새로운 Record를 생성한다.
- 동일 날짜와 행동의 기존 Record는 수정하지 않는다.
- `createdAt`과 `updatedAt`을 저장한다.
- 기록 생성 시각은 상세 화면에 표시하지 않는다.

### 성공 결과

- 기록 입력 바텀시트로 저장한 경우 바텀시트를 닫는다.
- 홈의 기록 요약을 갱신한다.
- 기록 횟수와 시간 합계를 갱신한다.
- 기록 완료 토스트를 표시한다.

### 실패 처리

- 탭 즉시 기록: 기록 실패 안내를 표시하고 홈 상태를 바꾸지 않는다.
- 기록 입력 시트: 바텀시트를 유지하고, 시간과 메모 입력값을 유지하며, 오류 메시지를 표시하고, 저장 버튼을 다시 활성화한다.

### 관련 정책

- 행동 수행 시각이나 시작·종료 시각은 MVP에서 입력하지 않는다.
- MVP에서는 소요 시간만 입력한다.
- 추후 `startedAt`, `endedAt`을 추가하여 확장할 수 있다.
- 기록에는 행동 이름·아이콘·카테고리 스냅샷을 저장하지 않는다.
- 현재 행동 정보를 `actionId`로 참조한다.

## REC-002 기록 입력 취소

### 기능 설명

기록 입력 시트에서 작성 중인 행동 기록을 저장하지 않고 닫는다.

### 처리 규칙

- 초기값에서 변경된 내용이 없으면 확인 없이 닫을 수 있다.
- 시간 또는 메모가 변경된 상태라면 이탈 확인을 표시한다.
- 취소를 확정하면 입력값을 삭제하고 바텀시트를 닫는다.
- 계속 작성을 선택하면 기존 입력값을 유지한다.
- 임시 저장 기능은 MVP에서 제공하지 않는다.

## REC-003 행동별 기록 상세 조회

### 기능 설명

선택 날짜와 행동에 해당하는 개별 기록 목록을 조회한다.

### 조회 조건

- `recordDate`
- `actionId`
- 현재 로그인 사용자

### 상단 요약

- 전체 기록 횟수
- 입력된 시간 합계
- `2회 · 50분` 형태로 한 줄 표시

### 개별 기록 표시

- 개별 기록 번호는 표시하지 않는다.
- 생성 시각은 표시하지 않는다.
- 읽기 상태에서는 기록 날짜를 반복 표시하지 않는다.
- 시간값이 없으면 시간 영역을 숨긴다.
- 메모가 없으면 메모 영역을 숨긴다.
- UI 확인 후 `시간 없음`, `메모 없음` 문구를 추가할 수 있다.

### 정렬

기본값은 최근 생성 기록 먼저다.

```
createdAt DESC
```

사용자 설정에 따라 오래된 기록 먼저로 변경할 수 있다.

```
createdAt ASC
```

### 목록 처리

- 기록을 바텀시트 내부 스크롤로 모두 표시한다.
- 별도의 페이지네이션이나 더보기 기능은 MVP에서 제공하지 않는다.
- 콘텐츠 높이만큼 바텀시트를 열고 최대 높이를 넘으면 내부 스크롤한다.

## REC-004 행동 기록 수정

### 기능 설명

기존 행동 기록의 날짜, 소요 시간 또는 메모를 수정한다.

### 관련 화면

- 기록 상세·편집 바텀시트
- 기록 완료 토스트의 `수정` (V1.1 추가)

### 수정 가능 항목

- `recordDate`
- `durationMinutes`
- `memo`

### 수정 불가 항목

- `actionId`
- `createdAt`

### Validation

REC-001의 날짜·시간·메모 Validation을 동일하게 적용한다.

추가로 다음을 검증한다.

- 기록이 현재 존재하는지
- 현재 사용자의 기록인지
- 저장 시점 기준 미래 날짜가 아닌지

### 처리 규칙

- `createdAt`은 최초 생성 시각을 유지한다.
- 수정 성공 시 `updatedAt`을 갱신한다.
- 사용자 화면에 `수정됨` 표시는 하지 않는다.
- 수정 후에도 기록 정렬은 `createdAt` 기준을 유지한다.
- 숨긴 행동의 기존 기록도 수정할 수 있다.
- 한 번에 하나의 기록만 편집할 수 있다.
- 수정 요청 중에는 해당 기록의 입력과 실행 버튼을 비활성화한다.
- 다른 기록 목록은 계속 확인할 수 있다.
- 날짜 유효성은 저장 버튼을 누르는 시점에 다시 검사한다.
- 시간 ± 버튼은 행동별 ± 단위를 사용한다. (V1.1 추가)

### 날짜 변경

기록 날짜를 변경하면 해당 기록은 변경된 날짜로 이동한다.

다음 데이터를 갱신한다.

- 기존 날짜의 기록 횟수와 시간 합계
- 변경 날짜의 기록 횟수와 시간 합계
- 기존 날짜의 빈 상태
- 변경 날짜의 빈 상태
- 현재 상세 상단 요약

### 성공 결과

- 편집 상태를 종료한다.
- 개별 기록 목록을 갱신한다.
- 상세 상단 요약을 갱신한다.
- 홈 요약을 갱신한다.

### 실패 처리

- 편집 상태를 유지한다.
- 입력값을 유지한다.
- 오류 메시지를 표시한다.

- 취소 확정 시 수정 전 값으로 복원한다.
- 임시 수정값은 저장하지 않는다.

## REC-006 행동 기록 삭제 (V1.1 변경)

### 기능 설명

개별 행동 기록 한 건을 영구 삭제한다.

### 관련 화면

- 기록 상세·편집 바텀시트
- 삭제 확인 팝업
- 기록 완료 토스트의 `되돌리기`

### 처리 규칙

- 기록 상세에서 삭제할 때는 확인 팝업을 표시한다.
- 기록 완료 토스트의 `되돌리기`는 방금 생성한 기록을 확인 팝업 없이 삭제한다.
- 삭제 후 실행 취소 기능은 제공하지 않는다.
- 휴지통이나 복구 기능을 제공하지 않는다.
- 선택한 기록 한 건만 실제 삭제한다.
- 같은 행동의 다른 기록은 유지한다.
- 숨긴 행동의 기존 기록도 삭제할 수 있다.

### 성공 결과

- 삭제 완료 토스트를 표시한다. (`되돌리기`로 삭제한 경우 생략할 수 있다.)
- 상세 상단 요약을 갱신한다.
- 홈 기록 요약을 갱신한다.

마지막 남은 기록을 삭제한 경우:

- 기록 상세 바텀시트를 닫는다.
- 홈에서 해당 행동 요약을 제거한다.
- 해당 날짜에 다른 기록이 없다면 기록 빈 상태를 표시한다.

### 실패 처리

- 기록을 유지한다.
- 현재 상세 화면을 유지한다.
- 삭제 실패 메시지를 표시한다.

### 삭제 충돌

다른 기기에서 이미 삭제된 기록에 수정 또는 삭제 요청이 들어오면 실패 처리한다. (API는 404를 반환한다.)

삭제된 기록을 새 기록으로 복구하지 않는다.

## REC-007 같은 행동 다시 기록

### 기능 설명

기록 상세 화면에서 현재 행동을 다시 기록한다.

### 처리 규칙

- 현재 기록 상세 바텀시트를 닫는다.

- 기존 기록을 복사하지 않는다.
- 시간과 메모는 새 기록의 기본값을 사용한다.
- 행동 기본 시간이 있으면 자동 적용한다.

# 5. 월간 캘린더

## CAL-001 월간 캘린더 조회

### 기능 설명

선택 월의 날짜와 기록 존재 여부를 조회한다.

### 표시 상태

- 홈에서 선택된 날짜
- 기록이 존재하는 날짜
- 현재 월에 포함되지 않은 앞뒤 달 날짜

## CAL-002 월 이동

### 처리 규칙

- 이전 달과 다음 달로 이동할 수 있다.
- 월 이동만으로 홈의 선택 날짜를 변경하지 않는다.

## CAL-003 캘린더 날짜 선택

### 처리 규칙

- 현재 월의 날짜와 앞뒤 달 날짜를 모두 선택할 수 있다.
- 앞뒤 달 날짜를 선택해도 추가 선택 과정 없이 즉시 적용한다.
- 선택 날짜가 포함된 주를 홈 주간 영역에 표시한다.
- 홈 상단 연·월을 선택 날짜 기준으로 변경한다.
- 홈 기록 요약을 갱신한다.
- 캘린더 바텀시트를 닫는다.

- 사용자 내 동일 이름 카테고리 생성 불가

- 생성 순서를 저장한다.
- 행동이 없는 카테고리 생성을 허용한다.
- 홈에서는 카테고리를 생성하지 않는다.

### 성공 결과

- 관리 목록에 새 카테고리를 추가한다.
- 현재 관리 화면을 유지한다.

- 입력값을 유지한다.

- 아이콘

## CAT-003 카테고리 숨김

### 기능 설명

카테고리를 삭제하지 않고 신규 기록에서 사용할 수 없는 상태로 전환한다.

### 진입 조건

- 활성 카테고리가 두 개 이상 존재해야 한다.

### Validation

- 마지막 활성 카테고리는 숨길 수 없다.

### 하위 행동이 있는 경우

숨김 전 다음 내용을 안내한다.

- 카테고리 안의 행동도 홈과 신규 기록 목록에서 표시되지 않음
- 과거 기록은 삭제되지 않음

### 처리 규칙

- 카테고리의 숨김 상태만 변경한다.
- 하위 행동 각각의 개별 숨김 상태는 변경하지 않는다.
- 과거 행동 기록은 유지한다.
- 행동 및 기록 데이터를 삭제하지 않는다.
- 홈 카테고리 목록에서 제외한다.
- 신규 기록 대상에서 제외한다.

### 마지막 카테고리 숨김 시도

- 숨김을 실행하지 않는다.
- 하나 이상의 활성 카테고리가 필요하다는 안내를 표시한다.

- 기존 생성 순서 위치로 복원한다.
- 카테고리 숨김으로 인해 가려졌던 활성 행동을 다시 표시한다.
- 카테고리 숨김 전부터 개별적으로 숨겨져 있던 행동은 계속 숨김 상태를 유지한다.

# 7. 행동

## ACT-001 홈 인라인 행동 생성

### 기능 설명

홈에서 현재 선택한 카테고리에 새로운 행동을 빠르게 생성한다.

### 진입 조건

- 로그인 상태
- 활성 카테고리가 선택된 상태
- 다른 행동 입력 상태가 열려 있지 않은 상태

### 입력 항목

| 항목 | 필수 | 설명 |
| --- | --- | --- |
| 행동 이름 | O | 최대 15자 |
| 행동 아이콘 | X | 미선택 시 기본 아이콘 |

### Validation

- 동일 카테고리 내 같은 이름 생성 불가
- 다른 카테고리에서는 같은 이름 허용
- 숨긴 동일 이름 행동이 있으면 신규 생성 불가
- 공백만 입력한 이름 저장 불가

### 처리 규칙

- 한 번에 하나의 행동 입력 상태만 연다.
- 다른 카테고리로 이동하면 입력을 취소한다.
- 기본 시간과 ± 단위는 홈에서 설정하지 않는다. (기본 시간 `null`, ± 단위 5분)
- 생성 행동을 현재 카테고리의 마지막 생성 순서에 배치한다.
- 생성 직후 자동으로 행동 기록을 만들지 않는다.

### 성공 결과

- 인라인 입력 상태를 종료한다.
- 새 행동을 행동 목록에 표시한다.
- 짧은 생성 완료 피드백을 표시할 수 있다.

### 실패 처리

- 입력 상태를 유지한다.
- 입력한 이름을 유지한다.
- 오류 메시지를 표시한다.

## ACT-002 관리 화면 행동 생성

### 입력 항목

| 항목 | 필수 | 설명 |

| 아이콘 | X | 기본 아이콘 적용 가능 |
| 기본 시간 | X | `null` 또는 1~1,439분 (COMMON-006) |

### 처리 규칙

- 홈 생성과 동일한 이름 중복 정책을 적용한다.
- 숨긴 카테고리를 소속 카테고리로 선택할 수 없다.
- 행동이 없는 카테고리도 허용한다.
- 기본 시간이 없으면 `null`로 저장한다.
- ± 단위를 선택하지 않으면 5분으로 저장한다.

## ACT-003 행동 수정

### 수정 가능 항목

- 행동 이름
- 아이콘
- 기본 시간
- ± 단위 (V1.1 추가)
- 소속 카테고리

### Validation

- 동일 카테고리 내 행동명 중복 불가
- 숨긴 대상 카테고리로 이동 불가
- 이동하려는 카테고리에 동일 이름 행동이 있으면 이동 불가
- 기본 시간은 `null` 또는 1~1,439분 (COMMON-006)
- ± 단위는 1·5·10·15·30·60분 중 하나

### 처리 규칙

- 이름과 아이콘의 변경 이력을 별도 저장하지 않는다.
- 행동 이름과 아이콘 변경은 과거 기록에도 현재 정보로 반영한다.
- 행동을 다른 카테고리로 이동하면 과거 기록도 현재 카테고리 기준으로 표시한다.
- 행동 기록에는 행동 정보 스냅샷을 저장하지 않는다.
- 기본 시간 변경은 과거 기록에 영향을 주지 않는다.
- 변경된 기본 시간은 이후 새 기록의 초기값으로만 사용한다.

### 성공 결과

- 관리 목록으로 이동한다.
- 행동 수정 완료 토스트를 표시한다.
- 홈 및 기록 요약을 현재 행동 정보로 갱신한다.

### 실패 처리

- 수정 입력값을 유지한다.
- 현재 수정 화면을 유지한다.
- 오류 메시지를 표시한다.

## ACT-004 행동 기본 시간 및 ± 단위 설정 (V1.1 변경)

### 기본 시간 입력 규칙

- 시간 없음: `null`
- 최소: 1분
- 최대: 1,439분
- 입력 단위: 1분

### ± 단위 입력 규칙

- 선택값: 1, 5, 10, 15, 30, 60분
- 기본값: 5분

### 처리 규칙

- 탭 즉시 기록 시 기본 시간을 그대로 저장한다. 기본 시간이 없으면 횟수만 기록한다.
- 기록 입력 시트를 열 때 기본 시간을 초기값으로 적용한다. 기본 시간이 없으면 `시간 없음`으로 시작한다.
- 시트와 기록 편집의 ± 버튼은 행동의 ± 단위만큼 시간을 바꾼다.
- 사용자는 개별 기록에서 시간을 수정하거나 제거할 수 있다.
- 개별 기록의 시간 변경은 행동 기본 시간에 반영하지 않는다.
- 기존 행동 기록에는 적용하지 않는다.
- 시간이 필요 없는 행동(예: 알약 먹기)은 기본 시간을 `null`로 둔다. 시간 영역을 숨기는 별도 설정은 MVP에서 제공하지 않는다.

## ACT-005 행동 숨김

### 기능 설명

행동을 삭제하지 않고 신규 기록에서 사용할 수 없는 상태로 전환한다.

### 처리 규칙

- 홈 행동 목록에서 제외한다.
- 신규 행동 기록 대상에서 제외한다.
- 과거 기록과 기록 상세에는 계속 표시한다.
- 기존 기록의 수정과 삭제는 허용한다.
- 행동의 `actionId`와 과거 기록 연결을 유지한다.
- 행동 영구 삭제는 실행하지 않는다.

### 열린 기록 입력 바텀시트

- 행동이 숨겨져도 바텀시트를 즉시 닫지 않는다.
- 저장 시점에 행동 상태를 다시 확인한다.
- 숨김 상태이면 신규 기록 생성을 차단한다.

## ACT-006 행동 재활성화

### 진입 조건

- 소속 카테고리가 활성 상태여야 한다.

### 처리 규칙

- 소속 카테고리가 숨김 상태라면 행동 활성화를 차단한다.
- 카테고리를 먼저 활성화하라는 안내를 표시한다.
- 활성화 성공 시 원래 생성 순서 위치로 복원한다.
- 기존 행동과 과거 기록을 그대로 사용한다.

---

## ACT-007 행동 카드 표시

### 표시 규칙

- 아이콘을 위에 표시한다.
- 행동명을 아래에 표시한다.
- 카드 높이는 일정하게 유지한다.
- 행동명은 최대 두 줄까지 표시한다.
- 두 줄을 초과하면 말줄임 처리한다.
- 실제 UI 검토 후 한 줄 말줄임으로 변경할 수 있다.
- 행동 버튼은 여러 열로 배치하고 자동 줄바꿈한다.
- 가로 스크롤을 사용하지 않는다.
- 탭은 즉시 기록, 길게 누르기는 기록 입력 시트를 연다. (V1.1 추가)

| 아이콘 | 선택, 미입력 시 기본값 |
| 기본 시간 | `null` 또는 1~1,439분, 1분 단위 |
| ± 단위 | 1·5·10·15·30·60분, 기본 5분 |
| 숨긴 카테고리 이동 | 불가 |

## 10-3. 행동 기록

| 항목 | 규칙 |
| --- | --- |
| 행동 | 활성 행동만 신규 기록 가능 |
| 날짜 | 오늘 또는 과거 |
| 시간 | `null` 또는 1~1,439분 |
| 시간 단위 | 1분 |
| 메모 | 선택 |
| 메모 길이 | 최대 500자 |

# 11. 핵심 데이터 관계

## 사용자

한 사용자는 여러 카테고리, 행동, 기록 및 설정을 가진다.

## 카테고리

- 한 사용자에게 속한다.
- 여러 행동을 가질 수 있다.
- 삭제하지 않고 숨김 상태를 사용한다.

## 행동

- 한 사용자와 한 카테고리에 속한다.
- 여러 행동 기록을 가질 수 있다.
- 삭제하지 않고 숨김 상태를 사용한다.
- 이름·아이콘·카테고리가 변경되면 과거 기록에도 현재 정보가 표시된다.

## 행동 기록

- 한 사용자와 한 행동에 속한다.
- 행동명, 아이콘, 카테고리 정보의 스냅샷을 저장하지 않는다.
- `actionId`를 통해 현재 행동 정보를 참조한다.
- 행동 기록만 실제 삭제할 수 있다.

# 14. 최종 핵심 정책

- 앱 사용 전 SNS 로그인이 필요하다.
- Google과 Apple 로그인은 독립 계정으로 처리한다. (구현은 Google 먼저, Apple은 출시 전)
- 앱은 할 일을 관리하는 투두 앱이 아니라 실제로 수행한 행동을 기록하는 앱이다.
- 행동을 탭하면 즉시 기록되고, 토스트로 되돌리거나 수정할 수 있다.
- 행동을 길게 누르면 시간과 메모를 입력해 기록할 수 있다.
- 같은 행동은 같은 날짜에 여러 번 기록할 수 있다.
- 모든 기록은 별도의 Record로 신규 생성한다.
- 시간과 메모가 없어도 행동 수행 횟수만 기록할 수 있다.
- 시간은 선택사항이며 1분 단위로 입력한다.
- 행동별 기본 시간은 신규 기록 초기값으로만 사용한다.
- 행동별 ± 단위로 시간 조정 폭을 정한다.
- 미래 날짜는 조회할 수 있지만 기록 생성·수정·삭제는 할 수 없다.
- 행동 기록에는 행동 정보 스냅샷을 저장하지 않는다.
- 행동명·아이콘·카테고리 변경은 과거 기록에도 현재 정보로 반영한다.
- 행동 및 카테고리는 영구 삭제하지 않고 숨김 처리한다.
- 숨긴 행동과 카테고리의 과거 기록은 유지한다.
- 행동 기록만 실제 삭제할 수 있다.
- 삭제된 행동 기록은 복구할 수 없다.
- 활성 카테고리는 최소 한 개를 유지한다.
- 로그아웃 시 로컬 사용자 데이터와 캐시를 제거한다.
- 회원 탈퇴 시 서비스 데이터를 실제 삭제한다.
- 탈퇴 후 같은 SNS 계정으로 로그인하면 신규 사용자로 시작한다.
